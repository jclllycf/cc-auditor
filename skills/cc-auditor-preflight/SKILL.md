# CC Auditor v3.6 发布候选：首次使用前环境预检

当前源码契约 `3.5.health.region.1`。新 Windows 构建须取得自己的真人授权回执，旧 v3.4 真实运行与自动测试不能证明新版本实机已通过。先调用 `audit_capabilities` 确认实际程序版本；若仍是 v3.4，按旧风险分解释，绝不能叫健康分。

## 唯一流程

1. 使用用户本机的非 Claude Agent；云端执行结果不冒充其电脑。
2. 调用 `prepare_deep_preflight`，再调用 `run_approved_deep_preflight(scan_id)`。本人在原生卡选择检测范围、已打开的日常 Profile、计划入口、API 实际发送方式和可选真实资格声明。Agent 不代点批准、不代填自述，不用 PIN、布尔值、旧会话或测试 mock 自我授权。
3. 仅在批准范围自动发现、读取、关联和复核。每源最多一次重试，额外预算 75 秒；保留失败和重试轨迹。取消立即停止后续有界阶段，不扩大范围、不停止用户应用。
4. 同一不可变 JSON 生成 `report_v3_6` 简明、完整技术两份中文 PDF；自动补证后仍有当前可补关键缺口，才生成证据补足清单。历史 JSON 离线重评必须明确没有新增测量，不覆盖旧报告。
5. 只向模型返回脱敏摘要、健康分、技术建议、地区观测边界、必要行动及本地文件路径；不粘贴整份配置、原始 Profile 或私人报告。`get_preflight_evidence` 最多十项。

## 核心判断

普通用户通常没有 Claude Desktop、CLI、SDK、账号或历史连接。这些是未来安装或实际服务事项，不能作为技术故障或当前必补证据。开发者现有 Claude 连接仅为获准研究校准资料，不是用户前提。

四端独立输出 `health_score` 0–100，越高越好；85–100 优良、70–84 良好、50–69 需关注、0–49 需优先整改。技术是否适合开始准备、实际服务是否已验证、覆盖、真实资格分别说明。健康分不是封禁概率，不保证注册、模型请求或付款成功。技术账本按适用权重归一化、同根因去重、缺口合计上限 20、关键严重阻断最高健康分 25；完整公式以代码及技术报告为准。全部缺测不能因数字高而判准备就绪。

未填写物理所在地或主体不扣技术分、不否决技术准备。IP、语言、时区、国籍、作息、Google Variations、代理品牌均不是主体资格证明，也不直接扣分。注册/支付资格在可靠实时政策未核对时写“需本人核对”，保留已有声明条件，不伪装确认符合或技术故障。

## API 执行位置

先区分本机 SDK、本机 Agent、云端 Agent、第三方网关、平台内置非 Claude 模型、未知。允许读取授权卡列明的运行应用名称/版本与宿主元数据；品牌不证明是否使用 Claude 或在哪里发送请求。

本机实际可测环境可评分；云端/网关/未知远端不借本机出口给 API 全链路打分。本机接入基础另列分数和范围，真实远端链路保持未测。平台内置非 Claude 模型为本次不适用，未选 API 不拖累 Web。不强迫任何 Agent 用户安装 Python/Node SDK。

## 地区与代理证据

逐视点输出中立 IPv4/IPv6、浏览器 HTTPS、UDP/STUN、DNS 递归结果和对应地理数据。只按相同公网 IP 关联已有国家数据，保留地理库分歧、协议/地址族差异及时间。通用测点出口不是 Claude 最终出口，代理标签和第一跳不证明最后国家。

网页可见的语言/请求头/时区/UA，与仅本地的 Windows Geo、Local State、Chrome Variations/永久一致性地区分别列。工具 origin 所见不等于 Claude 已收到。物理位置无法独立确认时保持未知，不能因缺 GPS、账号或自述扣分。

自动发现实际代理 GUI、内核、监听、配置与接管方式，按 Mihomo、Xray、sing-box 等真实适配能力分析。无 Claude 请求/历史 IP 时用离线符号规则分支。PAC、WPAD、浏览器独立代理、多内核及链式出口不能唯一归属时保留未知，不能借其他视点中立结果填充。

## 授权、隐私与网络

扫描器不主动访问或解析任何 Claude/Anthropic 目标；不打开、刷新、登录现有 Claude 页，不启动 Claude、SDK、用户项目或认证操作。既有进程/连接只在批准范围有界只读。不更改代理、节点、DNS、时区、身份、语言、证书，不提权，不安装组件或常驻监控。

`program_context` 只读卡内固定安装位置/PATH、相关浏览器限定参数、代理变量存在性、WinHTTP、指定项目依赖元数据和已运行 WSL/本机容器固定命令。不开停机实例，不连接 SSH/远端 Docker，不读取 .env、任意进程环境、Cookie、密码、Key、聊天、私人源码或付款资料。

`browser_dynamic` 仅复用已打开且本人确认的真实日常 Profile。不得用空白临时/无痕/Guest 档案代替日常资料。token 回调、定向启动和 PID 为有限归属证据，不叫不可伪造身份证明。

只有批准联网范围才访问卡内固定非 Anthropic 测点；无媒体授权、无 TURN、无登录扣款。第三方可记录最小 IP/DNS/TLS 元数据，工具摘要可进入 Agent 云模型，本地清理不能撤回外发。只清理工具自己的实验键和受控工件。

## 验收和交付

三份 PDF 使用同一 run_id/证据 SHA/评分版本。首页优先四端健康分、技术准备、地区边界和三类行动；详细版保留逐项状态、所有 Profile、账本、来源和自动尝试；第三份只列现在能补的资料，不要求未来安装或服务端秘密。

必须检查中文字体、PDF 实际提取、数字/布尔值与账本一致性及渲染几何。源码回归、离线重评、候选 EXE 冒烟、真人授权 Windows 扫描、真实代理矩阵分别记录，未完成不得宣布正式发布。中文字体私有加载，不安装到系统。
